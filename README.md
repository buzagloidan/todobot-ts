# Todobot

A self-hosted Hebrew WhatsApp task and reminder bot built with TypeScript and Cloudflare Workers. Send text or voice messages to create tasks, set recurring reminders, manage projects and checklists, share tasks, and optionally sync a dedicated Google Calendar.

The former hosted service is being retired. This repository contains the application, not access to an operated bot. Each deployment uses its own accounts, phone number, credentials and data. The source is [MIT licensed](LICENSE); Cloudflare, Meta, Gemini and other provider services have their own terms and usage charges.

## Architecture

Meta WhatsApp Cloud API → signed webhook → encrypted per-phone Conversation Durable Object inbox → Gemini task parsing → D1. ReminderScheduler Durable Objects and Cloudflare Queues deliver reminders; a minute cron recovers schedules. KV provides caching and soft rate limits. Drizzle ORM queries D1.

The conversation language is Hebrew, the timezone is `Asia/Jerusalem`, and workdays are Sunday–Thursday. This is not a locale-neutral bot. AI output is validated and task permissions/revisions are checked before mutations.

## Local setup

Use Node.js 24 or newer and npm. Tests and local D1 run without Cloudflare credentials and mock external APIs. Running a real conversation requires your own Meta and Gemini credentials, even locally.

```sh
git clone https://github.com/buzagloidan/todobot-ts.git
cd todobot-ts
npm ci
node scripts/init-dev-vars.mjs
npm run db:migrate:local
npm run check
npm test
npm run build
npm run dev
```

`init-dev-vars.mjs` creates an ignored `.dev.vars` with fresh local encryption, webhook-verification and app-secret values, without printing them. Replace the Meta app secret with your app's actual secret, and fill `ACCESS_TOKEN` and `GEMINI_API_KEY`. Never use the test suite's public encryption key with real data. Keep the encryption key backed up privately: replacing it does not re-encrypt existing records and will make them unreadable.

`npm run dev` simulates Cloudflare storage locally. The homepage is at `http://localhost:8787/`. To receive Meta webhooks, expose a development deployment through HTTPS and configure Meta accordingly. Calendar OAuth requires a public HTTPS host; it is disabled by default. No CI workflow deploys or needs production secrets.

## Deploy your own instance

1. Create a Cloudflare account with Workers, D1, KV, SQLite Durable Objects and Queues available under your plan. Use `npx wrangler login` with your own account.
2. Create dedicated resources:

   ```sh
   npx wrangler d1 create bot-db
   npx wrangler kv namespace create CACHE
   npx wrangler queues create wa-msg-dlq
   npx wrangler queues create wa-msg-queue
   npx wrangler queues create wa-reminders-dlq
   npx wrangler queues create wa-reminders
   ```

3. Edit `wrangler.toml`: replace the zero-filled D1/KV IDs with the returned IDs, choose a unique Worker/resource name if needed, and set `PUBLIC_HOST` to your HTTPS hostname without a scheme/path. Set `PHONE_NUMBER_ID` to your own Meta phone-number ID. The repository contains no original account IDs or phone number. The included placeholders work for local emulation, not production resource access.
4. Register your own Meta developer app and WhatsApp Business phone number. Set up the `messages` webhook subscription at `https://YOUR_HOST/webhook`, with your own verification token and app secret. Choose a supported `WHATSAPP_API_VERSION` for your Meta app; the default is `v25.0`. Approve the Hebrew `todo_reminder` template with body variables for task description and due time. Additional action, API and agenda templates are described in [task controls](docs/TASK_CONTROLS_AND_AGENDA.md) and [reminders](docs/REMINDERS.md).
5. Store required secrets using the interactive prompts. For an existing database, use its existing encryption key.

   ```sh
   npx wrangler secret put ACCESS_TOKEN
   npx wrangler secret put APP_SECRET
   npx wrangler secret put VERIFY_TOKEN
   npx wrangler secret put GEMINI_API_KEY
   npx wrangler secret put ENCRYPTION_KEY
   ```

   `.dev.vars` is only for local use; it is not uploaded by deployment. `ENCRYPTION_KEY` uses the legacy double-base64url format generated by `init-dev-vars.mjs`.

6. For a **new, empty** D1 database, run `npm run db:migrate`. This explicitly applies migrations remotely. `migrations/` is the ordered SQLite chain, excluding the archived PostgreSQL queue cleanup and date-specific customer-trial backfill. It retains legacy tables for compatibility. **Existing installations must reconcile their applied schema before adopting this migration history**; do not replay the initial schema against a populated database. `drizzle/` holds the original migration archive. Its Drizzle journal is incomplete; do not use `drizzle-kit migrate`, or generate destructive schema cleanup from it.
7. Set `SUPPORT_EMAIL` to your operator contact. Review the built-in Hebrew `/tos`, `/privacy`, homepage and public policy pages for your deployment's actual behavior and retention. Then run `npm run check`, `npm test`, `npm run build`, and explicitly run `npm run deploy`. Configure your custom domain in Cloudflare if using one; otherwise use your assigned Workers hostname in `PUBLIC_HOST`. Confirm a real webhook and reminder with your own test number before inviting users. Automated tests do not verify live provider configuration.

Useful commands: `npm run types` regenerates binding types after config changes; `npm run tail` reads your deployed Worker logs.

## Optional integrations

| Feature | Configuration |
| --- | --- |
| Subscription billing | Off by default (`BILLING_ENABLED="false"`). Tasks, reminders and API access do not expire. To operate the original seven-day/₪20 ILS plan, see [billing](docs/BILLING.md). Turning billing off does **not** cancel existing provider subscriptions. |
| Google Calendar | Off by default. Requires your OAuth client, public host and explicit data-handling flags. See [Calendar setup](docs/GOOGLE_CALENDAR.md). |
| PostHog | Omit `POSTHOG_API_KEY` to disable. When configured, sends pseudonymous usage events to the PostHog EU endpoint. |
| Feedback email | Requires `RESEND_API_KEY` plus your verified `FEEDBACK_FROM` and destination `FEEDBACK_TO`. Missing configuration sends no email and reports a failure to the user. |
| Operator alerts | Set your own `ALERT_PHONE` (international digits). Blank disables WhatsApp operator alerts. |
| Bot referral link | Set your own `BOT_WHATSAPP_NUMBER` (international digits). Blank disables referral prompts. This is the public number, not the Meta phone-number ID. |

## Data and security

Phone numbers, task descriptions, messages, project names and OAuth credentials are encrypted in storage. Phone hashes, timestamps, IDs, relationships and billing metadata are not encrypted; SHA-256 phone hashes are pseudonymous, not anonymous. Plaintext necessarily reaches Meta and Gemini to deliver/process messages. Optional feedback sends the submitted text and last four phone digits to your configured email recipient through Resend.

The legacy `/api/v1/:secret` notification endpoint embeds the user's token in its URL. Treat the entire URL as a credential, keep access logs/analytics private, and rotate it using the bot after exposure. User deletion and provider cancellation are separate from operator shutdown. See [shutdown and release checklist](docs/OPEN_SOURCE_RELEASE.md), [security policy](SECURITY.md), and [contributing](CONTRIBUTING.md).

This is a source-release readiness review, not a comprehensive penetration test. Live billing, Meta approvals, OAuth consent and provider delivery require operator verification. The four remaining npm audit findings are moderate and limited to Drizzle Kit's legacy esbuild development-server dependency; do not expose Drizzle Studio/development tooling to untrusted networks. Production dependencies pass `npm audit --omit=dev`.
